# T01 — Adaptive circular growth in a live neighborhood

**Operation stages:** 1 + 1.5  
**Prerequisite:** T00  
**Autonomy:** Implement/iterate/verify within T01, then **commit and STOP for owner review**. T02–T07 are not authorized.


## Objective
Produce the first visible multi-site transformation on the owner crop: nominal circular growth becomes locally adapted copper in response to already accepted neighboring shapes.

## Implementation
Introduce the smallest working-scene adapter over existing geometry/catalogue facilities. Track scene revisions, protected cores, source contributions and trace reservations. Update or invalidate affected spatial entries after each accepted atomic patch.

For each selected circular feature, construct nominal growth from ORG and the frozen policy. Query the current scene. Fit optional growth inside the ORG-derived influence region while respecting earlier accepted copper, required gaps, protected source geometry and future routing envelopes. Keep or abstain when appropriate. Accept only connected, attributable growth attached to the feature, not remote islands.

Implement one deterministic priority policy; allow selected round outlines only when justified by the source-only policy and feasible. Do not impose one round anchor per entire physical component. Record each nominal versus accepted shape, limiting neighbors, input/output scene IDs and adaptation reason.

Run the main crop, not just a tiny example. Tiny mechanism fixtures support verification but never replace the actual neighborhood output.

## Verify
- In a two-target competition control, the later proposal sees the earlier accepted enlargement and adapts or rejects accordingly.
- A stale spatial index or wrong scene revision is rejected or rebuilt; it must not silently return stale feasibility.
- At least three actual crop events are sought where a changed neighbor materially influences the later shape; record whether obtained.
- Protected cores, reference geometry and ports are preserved; no new contact between distinct protected components.
- Any optional cutting applies to newly proposed growth unless a separate current-stage permission explicitly allows more.
- Same order/policy/ORG replays to the same canonical geometry. Withholding EDIT does not alter construction.
- Compare a static-ORG-neighbor baseline with dynamic decisions under the same parameters. A test count is not evidence of better target fit.

## Perceivable output
Full crop: ORG versus accepted circle-stage scene. Select one site to see nominal growth, an earlier neighbor's enlarged boundary, and the accepted asymmetric result. The event explanation must name the actual neighbor and constraint.

## Completion and mandatory stop
Run the real full-crop experiment and focused tests; separately report implementation completion, technical PASS/FAIL, *actual dynamic neighbor-adaptation events* (target at least three; if fewer, report actual count and PARTIAL where appropriate), static-baseline comparison, and visible outcome. Do not claim T01 complete from tests alone when the real-crop interaction is absent. The future 20% whole-crop EDIT residual objective belongs to T06, not T01.

Retain failed patches and blockers. Produce a source-bound compact audit receipt, whole-crop before/stage view and actual interaction detail; run relevant regressions. Commit only owned local changes, report exact commit and worktree status, then **STOP** regardless of PASS/PARTIAL/BLOCKED. Wait for owner review and separate authorization before T02; no remote push without permission.
