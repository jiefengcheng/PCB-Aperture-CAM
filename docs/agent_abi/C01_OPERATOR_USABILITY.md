# C01: ordinary English above an audited native route

The human request can be: “Show the expanded C01 terminals from the exported
KiCad and Gerber files side by side, and check the result.” The project AGENTS.md
maps this bounded intent to the reusable operator entry point. Users do not
provide paths, viewport numbers, operation IDs, hashes or audit JSON. This is a
project-configured bounded language workflow, not a general English compiler.
Other crops, source edits, expansion requests and later stages are unsupported.

## Reduced interaction, unchanged audit obligations

One stdlib client now owns the mechanical fields and state. It uses the same
macOS mailbox, native runner and three render ABI operations. The human sees
ordinary English; the configured agent makes four small calls:

1. `python3 tools/pcb_c01_operator.py start` renders one slice and returns compact
   actual facts for review.
2. `... review "one short observation"` rechecks the original native receipt,
   binds the agent note to the displayed summary, and submits the exact same
   four-field native audit as before. Only native acceptance permits the next
   slice to execute.
3. A second review gates verification before controls.
4. A third review gates controls and returns a terminal delivery receipt.

There is no automatic approval and no loop through all stages. Each of three
agent observations remains mandatory. Every original native check, digest/fact
comparison, source/output hash, raster tolerance and negative control remains.
Mechanical fields are copied by code from verified receipts; observation notes
are supplied by the agent. They remain consistency observations, not independent
geometry or owner acceptance.

The first English-only trial reached all three native checks quickly but hit an
unnecessary client note-length limit on its third observation. It stopped and
did not retry. That failure is retained. Full natural-language observations now
remain verbatim in review records, with their SHA256 reference in the unchanged
native short-note field. No note is truncated. Summary hashes, exact native audit
fields and native-owned audit requests are cross-checked before continuation.
The compact result also states that each image is checked against its own input;
it cannot establish new cross-file parity or aperture-mask stability. Terminal
responses supply a concise, properly scoped human report.

Compact responses retain all native facts, measured raster bounds and actual
negative-control results. Full raw evidence stays on disk. The terminal response
supplies paths, file formats, byte counts, PNG dimensions and hashes, then says
REPORT_AND_STOP. A failure is latched HALTED; subsequent facade calls cannot
retry it. Repeated terminal calls only recheck the existing artifacts and cannot
execute another slice. The facade does not sandbox the agent's other tools;
actual absence of extra probing must be established in the live trial.

## Repeatable macOS setup

Start once, in the project native environment:

```sh
.venv/bin/python -B tools/start_c01_render_operator.py
```

This foreground launcher creates a fresh session and publishes the project-local
active binding under `out/operator_routes/c01_render/current.json`. Previous
bindings and session evidence are preserved. The stable entry point discovers
that binding; no per-agent path/parameter brief is required. Ctrl-C stops the
launcher. No daemon, package installation, global configuration, network listener
or MCP is added. A prepared native runner is a setup requirement; ordinary
English is not claimed to bootstrap a missing native execution environment.

The narrow discovery rule in AGENTS.md is the agent-facing customization layer.
The native contract still fixes the two session306 inputs and the C01 viewport.
A fresh Local Code chat must demonstrate that it acquires this rule from project
context using an ordinary-English request, with no coordinator briefing or
per-step help. Successful execution will qualify only that observed bounded
intent and route, not arbitrary language understanding or general ABI mastery.

Evidence namespace: `out/crop_dynamic_tasks/t01_operator_usability_20261101_310/`.
Session309 remains sealed and is never overwritten. Frozen C01/C02/C03, T01
geometry/clearance semantics, T02-T05, owner and manufacturing decisions remain
unchanged.

## Observed results and remaining host limitation

The corrected ordinary-English run_v2 passed all native gates in124.829s, but
failed tool discipline. Its visible transcript included a script-existence
probe, a directory list and a final pwd/output listing. Native success was not
treated as passing the no-probe requirement. The separate run_v3 sharpened the
reusable entry/completion rule: first tool action is start, only four facade
commands and their completion polls are needed, and the final PNG uses the
returned absolute path. It also requests a concise final report instead of
repeating the retained hash tables and audit details.

The final trial reached the third observation audit in109.221s, compared with
624.654s originally. The same English request was used in a fresh chat with no
technical brief or follow-up prompts. Final UI/tool-discipline observations and
full-chat duration are recorded separately in the session310 assessment; they
must not be inferred merely from native call counts. The earlier failures remain
preserved.95 focused tests pass, with all original raster checks and four negative
controls unchanged.

Read-only inspection of the currently exposed Local Code Settings/Kit controls
found folder/app permissions, model preferences and reasoning settings, but no
per-command tool allowlist. Low/1280 and all settings were left unchanged. The
facade can enforce its native gate order and latch failures; it cannot prohibit
Local Code's other tools. Clean behavior in an observed trial is a behavioral
qualification, not a sandbox guarantee. Reliable enforcement for another host
requires that host to expose only the bounded operator actions (plus completion
polling) or apply a command allowlist. More prose alone cannot provide enforcement.

Final observed outcome: run_v3 displayed the actual comparison and completed its
response in 2m21s (Local Code UI), with four facade commands and normal completion
polls. No file/directory/environment probes were observed. However, it issued
one extra terminal `true` command. The strict only-permitted-commands criterion
therefore remains FAIL; it is not waived because the command is harmless. Bounded
English usability and the speed target passed; enforced tool discipline is not
qualified. Do not keep retrying instruction variants or claim that a project
facade can sandbox an app's other tools. This remaining boundary requires host
tool restrictions, which are not exposed by the currently inspected app UI.

Post-trial code review strengthened missing-record detection: a completed cached
delivery must retain all three full observations and all three native audit
requests. Deleting either record, or both together, now fails closed.98 focused
tests pass. The stronger guard also verified the actual completed run_v3 records
read-only, without another ABI execution. Timing and live English behavior refer
to the pre-hardening source snapshot; no new native or English timing is claimed
after this custody-only change. Both source snapshots and the change assessment
