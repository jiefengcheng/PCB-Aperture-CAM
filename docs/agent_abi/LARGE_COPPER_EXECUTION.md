## Milestones and current support

1. **Execution custody:** explicit Gerber source, original revision, implementation
   and policy binding; source-wide process lock; durable duplicate-job receipts;
   progress; immutable successful results and retained failures.
2. **Discovery and construction:** a sequential survey of every authenticated
   broad original owner ring, then shared T02/T05 32-edge preparation for the
   admitted straight-flank feature batch. Unrelated objects do not retain indexes.
   No board ordinal, saved window, pinned parent, or expected success count is
   consumed. One `CleanupBatch` prepares neighbours and constructs local cuts,
   followed by affected-dependency checks and assembled material validation.
3. **Saved delivery:** CLI and the native **Run large copper trimming…** action
   invoke `tools/run_large_copper.py`. Fully validated results publish into a new
   job-local viewer session. Native display acknowledgement is checked separately.

These milestones implement a bounded reusable profile, **not general defect
discovery or complete arbitrary-board cleanup**. Curved/short boundary sections
are inventoried as unsupported, never called successful treatment. The previous
circular-pad/round-endpoint examples remain qualification evidence; their pinned
angular sectors and windows have not become generic discovery.

The source parser is the existing maintained Gerber intake: absolute MM L46,
L33 and explicit legacy T35 profiles, supported circular/rectangular apertures,
lines/arcs/regions and existing ordered dark/clear composition. Unsupported
semantics stop with evidence. Clear-clipped traces/flashes retain the existing
unsupported-family rejection. An explicit X2 non-copper or negative file role
rejects. An unannotated legacy file is the user-selected positive copper
computation surface; no stack role or independent electrical intent is inferred.

Discovery currently admits two collinear original boundary supports of at least
0.020 mm, with a complete intervening protrusion span at most 1.000 mm. These are
discovery-profile bounds, not relaxed geometry tolerances. All rings are visited;
the profile does not claim to identify every defect on them. A degenerate span
or recess is not a protrusion. Overlapping alternative references remain
unresolved together. A cause must contain the entire physical bump; exact source
aliases are one cause. Distinct plausible causes are ambiguous. A nearby large
pad or connected fill cannot become the denominator.

Area noise remains strictly below 10% of the **original causing pad/trace**.
Overlapping draws share the complete physical numerator and cumulative removal
check. The separate shallow-source-edge path uses the existing depth/half-width,
native path and straight-support proof; it is never applied to a pad. The
0.100 mm depth maximum, 0.004 mm circular fit bound and existing numerical
tolerances remain. The shared registry cannot enlarge these execution limits.

All native flashes and rectangles are protected in this first independent
profile. Generic pad trimming and redundant-endpoint-flash exemptions are **not
enabled**: the case-specific proofs do not justify inferring exemptions for an
arbitrary input. Rectangular causes are ignored; ambiguous/pad/protected/path/
contact/depth failures are saved unchanged with reasons. Original paths, centres,
original contacts, protected domains, source order and physical topology remain
protected. This intentionally need not reproduce all 46 reviewed local cuts.

## Commands

Run preparation first, then supply an absolute source file path:

```sh
tools/Prepare_LaCie_Workspace.command
.venv/bin/python -B tools/run_large_copper.py run --source '/ABSOLUTE/source.gbr' --prepare-display
```

Optional `--output out/lacie_work/UNIQUE_JOB` chooses a new job location. Otherwise
the runner allocates one under `out/lacie_work/large_copper_jobs/`. Stdout is one
JSON result; stderr has progress events. No existing output directory is reused.
The native action opens a one-file picker, calls this exact CLI and switches to
the new saved session only after successful validation/publication. The previous
session is retained. Navigation, filtering and playback never call execution.

```sh
.venv/bin/python -B tools/run_large_copper.py status --job '/ABSOLUTE/JOB'
.venv/bin/python -B tools/run_large_copper.py prepare-display --job '/ABSOLUTE/JOB'
tools/Start_Gerber_Viewer.command --workspace '/ABSOLUTE/JOB/viewer'
```

Use the returned `display.workspace`, which can differ from `JOB/viewer` after
an explicit `prepare-display --new-revision`. This creates another saved display
derivative after a presentation correction; prior sessions/receipts and geometry
remain unchanged. It never resumes a geometry job. Failed display publication
requires a changed implementation before another explicit derivative is allowed.

Display states distinguish `NOT_REQUESTED`, `PENDING_NATIVE_ACK`,
`NATIVE_DISPLAY_ACKNOWLEDGED` and retained display failure. An enqueued or prepared
snapshot alone is not native display evidence. The dedicated view contains grey
original large copper in every state, optional pink removal ghosts, saved rule/
status/object filters, Original/Corrected/Comparison and saved-only Play.

Source+policy+implementation duplicate requests return the retained job, including
its failure, instead of re-running. Different output paths do not bypass the
source lock. A crashed worker is `INTERRUPTED_RETAINED_NO_AUTOMATIC_RETRY`;
failed jobs are not resumed or resealed. Corrected implementations use new jobs.
Missing source intake retains errno/path. Corrupted preparation/artifacts stop;
there is no internal-storage fallback or silent cache replacement. Interrupted
display derivatives do not replace a committed display. Saved status/authentication
checks byte custody and do not rerun geometry acceptance.

`CopperContext` retains exact native preparation during the worker and
authenticates its reopen. Its 128 MiB indexed and 192 MiB snapshot limits remain;
discovery additionally rejects excess transient ring operands within the indexed
budget. These estimates are not RSS caps. Reports measure peak process RSS and
intake, preparation, discovery, construction, validation and display preparation
separately. No runtime estimate or future savings is established for arbitrary
sources.
